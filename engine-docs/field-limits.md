# Canvas field limits

This is the single source for what Canvas keeps, changes, or shows in each field the Engine writes. Agents read it with `cse help fields`. Other documents link here instead of restating limits; when evidence changes, change this file (and the capability records) and nothing else. `help formats` says what the Engine accepts; this file says what Canvas does with it.

Evidence levels, strongest first:

- **Live API**: the Engine (or an API call) wrote the field in Canvas Live and read it back. Proves storage, not what people see.
- **Live view**: a person looked at it in Canvas (teacher view, Student View, SpeedGrader, or quiz preview; the row says which).
- **Editor**: written or read through Canvas's own editor. Shows editor behavior, not what an Engine write stores.
- **OG**: a record or rule from the original CanvasExpert or QuizForge, not re-checked here.
- **Unknown**: not measured. Treat the field conservatively.

CE-SE has no HTML allowlist of its own. Assignment creates and assignment Hub pages use the Engine's Markdown subset, which emits only `p`, `h1`–`h6`, `ul`/`ol`/`li`, `pre`/`code`, `strong`/`em` (from `**bold**`, `*italic*`, `_italic_`), and `a` to course pages or http(s); anything else is escaped and shows as text. Quiz HTML is sent as written, except that the Engine re-renders `<pre><code>` in item prompts as its code box, wraps plain choice or feedback text in `<p>`, and replaces em dashes (see `help formats`).

## For review previews

Render the exact Engine payload. Plain-text fields display as plain text, and the preview copies the display behavior recorded above rather than looking better than Canvas. HTML fields render in a sandbox with scripts off; markup not recorded as kept on that field is flagged "not verified." Make no claims about the student view or the quiz player unless the row records a Live view.

The probe reports and payloads behind these verdicts (2026-10-10, CS8) are in the source repository's Git history.

### Selected-club individual audiences (2026-10-19)

Assignment create and initial assignment-dates updates support `audience.mode: individual`, `policy: snapshot` and one exact collaborative source set plus unique positive group IDs. The Engine expands selected clubs to active enrolled students with accepted membership, using the existing private identity store. Pending/invited/unresolved facts hold publication; known inactive/completed enrollments are excluded explicitly. Empty audiences are valid drafts. Student-only override creates may omit dates; no synthetic deadline is required. Initial audience updates preserve existing manual exceptions and current publication. Explicit refresh returns a separate assignment-dates action with exact owned-row changes and current/history work protection. Course Pages and New Quizzes accept the same intent through their own contracts below. Dates-only override updates preserve all currently overridden values and their overridden/inherited presence, including explicit null.

Refresh removals require readable exact student/assignment evidence, including returned submission history; unknown evidence retains access. Genuine current/history work and grades protect students by default. Student IDs remain private, and only Engine-created exact owned rows may change. Safe independent removals can proceed while newly protected members remain in that same row. Update payloads retain all current overridden dates, including null. An owned row with zero remaining recipients uses its exact DELETE endpoint. Saved create receipts and pending/uncertain outcomes remain intact.

### Course Page audiences (2026-10-19)

A course Page accepts the same `audience` intent plus `observed_dates`, `unlock_at` and `lock_at`. `observed_dates` records the exact date-details baseline: `only_visible_to_overrides`, `visible_to_everyone`, the Page's availability dates and every override row with its exact ID and one supported target (group, section or private student refs). A collection write replaces every row, so an unknown or unmappable row holds the replacement rather than being dropped. Canvas documents `204 No Content`; success is accepted without returned override IDs, and a later identity-dependent action resolves its own exact rows. Pages have availability dates and no graded due date. `unlock_at`/`lock_at` are optional edits: omission preserves the observed value and `null` clears it. Group Pages and Hub tier Pages reject this contract.

### New Quiz audiences (2026-10-19)

A QuizForge file accepts the same `audience` intent in `metadata.canvas.audience`. The quiz resource routes use the associated assignment ID, so the restriction targets that exact assignment; a quiz whose assignment is native group work is refused. The sidecar records `instance`, `course_id`, the prepared audience and per-stage outcomes (`items`, `settings`, `audience`, `module`, `publication`), so a resume repeats only unfinished stages. A sidecar bound to a different Canvas or course is refused. Sidecars with only `assignment_id`/`tier_pages` remain usable and gain no stage records. Audience application precedes publication; a failed or uncertain audience leaves the quiz unpublished. Audience-only refresh returns an `assignment-dates` action and sends no quiz, item or settings write. New Quiz attempts and grades protect removals.

### Club units in a shared module (2026-10-19)

A club unit is three independent resources sharing one audience: a course Page, an individual assignment and a New Quiz. Each is prepared, reviewed and pushed separately, so a held resource never blocks the others. The module is a navigation list and carries no audience; each child keeps its own restriction. Push the resources before the module so every native reference exists. An existing module keeps its unrelated entries and gains one native entry per resource in the requested order; a New Quiz entry uses its associated assignment ID, and a restricted course Page is an ordinary native `Page` entry rather than a group `ExternalUrl`. Membership refresh is per resource; assignment and quiz removals are work-protected, Page removals are not.
