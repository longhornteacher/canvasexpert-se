## Findings and corrections

- **Membership requests and recovery — `4ed7eac`.** Pending self-sign-up requests were counted but absent from the editable baseline. An explicit placement could consequently treat a newly requested membership as unassigned. Rosters/baselines now retain pending requests using stable student refs and group IDs; current requests hold that student's placement. Unmapped request authors make the roster incomplete. Accepted/preserved membership actions no longer replay after later manual changes. Uncertain actions reconcile from a current roster or remain uncertain, including when a reread fails; they do not become retryable merely because the outcome is unresolved. Returned invited/accepted state stays accurate. A pulled membership baseline is now valid before changes are added; previously validation prevented saving it.
- **Assignment-date recovery — `5245043`.** Saving an accepted override's ID into a create row made the next invocation fail validation, blocking unfinished independent rows. Matching accepted create state now validates. Pending/uncertain override and create-stage visibility outcomes remain unresolved across repeated resumes instead of becoming retryable held actions. Standalone visibility now saves its target and outcome, so accepted work is not replayed after a later Canvas change. Uncertainty remains reported as incomplete even when the current setting matches. Requested visibility cannot be silently treated as not requested.
- **Group/discussion REST payloads — `603fb80`.** Group-set create/update, group create/update, and discussion create/update/publication used nested `group_category`, `group`, or `discussion_topic` envelopes. Canvas's REST handlers consume these fields at the top level. This could reject creates or accept edits without applying their intended fields. All seven call sites now send flat fields, with fixtures that check actual request bodies. The documented `wiki_page`, `module`, `module_item`, `assignment`, and `assignment_override` envelopes remain appropriate.
- **Discussion audience and observed identity — `603fb80`.** An update checked topic ID but not a changed live group set, linked assignment, or announcement identity. Updates now hold on those changes, preserve the unsent source document and save a fresh baseline using live identity. The baseline includes optional linked `assignment_id`. Announcement baselines can be pulled without inventing communication intent; actual announcement writes still require explicit intent.

Final correction commit and check outcomes are recorded in the active handoff's review checkpoint.
