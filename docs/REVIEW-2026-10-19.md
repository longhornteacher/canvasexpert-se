## Additional findings

### P2 — Shared timing completion can follow only the representative

Locations: `internal/workflow/group_post.go:705`, `:787`, and `internal/workflow/late_timing.go:107`.

During an uncertain shared late-only resume, each member passes the renewed check if either their original baseline remains or the proposed timing is present. The code then delegates completion to `postLateTiming` for the representative alone. If that student matches the target while the other members retain their original timing, the whole group action becomes `preserved` with zero writes.

Reproduction: start with the existing three-member group fixture, prepare late-only results, set the saved outcome to `uncertain`, and expose the requested timing only for the selected representative. The returned group outcome is `preserved`; the other two members do not match. The existing `TestPostGroupLateOnlyReconcilesUncertainWriteWhenEveryMemberMatches` covers only the all-matching case.

Correction: reconcile shared completion against every renewed audience member before marking it preserved. Mixed uncertain states must remain held/uncertain without a blind retry. Keep this check in the group workflow; an individual timing helper cannot establish whole-group completion.

### P2 — Timing provenance depends on filename and folder

Locations: `internal/workflow/session_discovery.go:35`, `internal/workflow/late_prepare.go:482`, `:549`.

All three timing-history scans search only `.md` files beneath `courses/`. Posting accepts a results path without those restrictions, and MCP draft writing explicitly supports `.yaml` and `.yml`. An accepted result can therefore be valid for posting but invisible to later timing discovery and preparation. With an explicit CE-SE `none` status, discovery can stop reconsidering that attempt even when calendar inputs change; an explicit `late` result can lose the provenance required to prepare a correction.

Reproduction: an accepted group late-only `.md` result is found by `acceptedTimingRecordExists`. Rename that same file to `.yaml`; the same identity lookup returns false. Folder exclusion is confirmed by inspection of the scan roots. The older academic completion scan searches the whole UserInstall, so the two kinds of completion already disagree about location.

Correction: align discovery with the supported result-file contract and reuse a small common result enumeration routine across these scans. Preserve exact instance/course/assignment/student/attempt checks. No new database, persistent index or migration is needed.

### P2 — Feedback withholding depends on grade-field presence

Location: `internal/workflow/parent_report.go:566`.

`gradeNotReleased` requires `posted_at: null` plus at least one non-null score, entered score or grading timestamp. When all three grade fields are null, teacher comments still enter `corrections.teacher_comments` in the parent packet. The stated scoring contract says an explicit null posting timestamp withholds feedback as well as grades.

Reproduction: decode a submitted, visible, in-window response with `posted_at`, `score`, `entered_score` and `graded_at` all null and one teacher comment. The comment appears in the saved-report classification. The existing privacy test always supplies scores and a grading timestamp, so it does not exercise this branch.

Correction: make feedback withholding follow the posting-state rule independently of numeric-grade availability. Keep the inventory row and honest ungraded status. This is a demonstrated contract violation in local classification, not proof that a real Canvas-hidden comment or email was disclosed.
