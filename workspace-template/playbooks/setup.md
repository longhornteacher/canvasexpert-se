# Set up CE-SE

Do this the first time, and on each new computer (the Canvas credential stays on each machine). The teacher only talks to you and enters their Canvas token in the local form; you do everything else, including editing `context/` files.

1. **Read saved setup and check the Engine.** Read `list_courses` with its default `source: configured`, or inspect the structured `courses` list in `context/courses.md`. Keep saved nicknames and current selections; ignore obsolete starter text in the body. This configuration read needs no Canvas credentials or network. Run `.\cse.cmd version`. If it says the program was not found, the folder is incomplete: ask the teacher to unzip the full CanvasExpert-SE download again.
2. **Connect this computer.** Try `list_courses` with `source: canvas` through MCP, or `.\cse.cmd courses` locally. If it succeeds, the existing saved connection works; keep it and continue with course configuration. Otherwise tell the teacher they'll need a Canvas access token and how to get one: in Canvas, Account, then Settings, then **+ New access token** under Approved Integrations; give it a purpose like "CanvasExpert-SE", leave the expiry blank or set it for the end of the school year, then copy the token. Use `start_local_ui` with `page: setup`, or run `.\cse.cmd setup`; it opens a private local form for the Canvas address and token (if the browser doesn't open, give them the printed local address). The token goes to Windows Credential Manager. Never let it be pasted into the conversation, the terminal, a file or a note. Setup records the Canvas address in `context/courses.md`.
3. **Configure missing or additional courses.** If the saved structured list already contains the requested courses, keep it and continue; do not repeat completed setup. When the teacher needs additional courses, `list_courses` with `source: canvas`, or `.\cse.cmd courses`, lists the Canvas catalog and IDs. Show the teacher the list and ask what they call each class they want to use, and which are current (the ones a "scoring session" should scan). Write their answers to `context/courses.md` (field reference in `help formats`); don't infer nicknames from Canvas titles.
4. **Student notes.** `.\cse.cmd students` changes aliases and monitored status. Teacher-written accommodations and notes go in `context/students.md`, tied unambiguously to a student and course; real names are fine there. Offer this; don't require it.
5. **School calendar.** Lateness depends on `context/school-calendar.md`. Ask the teacher for the school's first and last days and holidays (or a calendar link or file) and fill it in. Offer this; don't block other work on it.

Then do what the teacher originally asked.

The hub and MCP use the same local CE-SE installation. The teacher does not choose a separate CE-SE workspace or copy course configuration to an agent's synced folder. `list_courses` reports the installation root, instance and saved `current` flags; another configured read sees hub changes without a restart. An existing MCP registration pointing at an old folder needs to be re-registered for the intended installation and restarted, rather than recreating course choices there.
