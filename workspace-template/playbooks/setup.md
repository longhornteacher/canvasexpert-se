# Set up CE-SE

Use `install.md` first when the teacher says "install this" or needs their agent app connected. This playbook handles Canvas, courses and progressive teaching context after Engine access exists. Do this the first time, and on each new computer (the Canvas credential stays on each machine). The teacher only talks to you and enters their Canvas token in the local form; you do everything else, including editing `context/` files.

Work in **Install**, the local runnable CE-SE folder. **Source** is for developing the product. Optional **Sync** is a dedicated locally accessible cloud directory holding authoritative teacher rules; the provider synchronizes it. The default needs only Install. MCP's "workspace" remains Install, and logical rule paths use the same active files as the hub.

For shared rules across PCs, first inspect `engine_info` rules-location status or `.\cse.cmd rules-location`. Only after the teacher supplies a dedicated directory, select it in Settings → Teacher rules, or use `.\cse.cmd rules-location --sync "PATH"`. An empty directory starts from this Install's actual customized rules; an existing directory wins without importing this PC's differing rules. Original local instructions are preserved and become inactive. On each PC, configure its own local path to that same provider directory. Do not point MCP registrations or `--workspace` at Sync. No manual copying between PCs is required. To return explicitly to local rules, use Settings or `.\cse.cmd rules-location --local`; current readable shared rules are preserved locally and differing local files are archived. If Sync is unavailable, restore access or explicitly select another rules directory; do not read inactive local copies.

1. **Read saved setup and check the Engine.** Read `list_courses` with its default `source: configured`, or inspect the structured `courses` list in `context/courses.md`. Keep saved nicknames and current selections; ignore obsolete starter text in the body. This configuration read needs no Canvas credentials or network. Run `.\cse.cmd version`. If it says the program was not found, the folder is incomplete: ask the teacher to unzip the full CanvasExpert-SE download again.
2. **Connect this computer.** Try `list_courses` with `source: canvas` through MCP, or `.\cse.cmd courses` locally. Success means the saved connection works; preserve it and continue. If the Engine specifically reports an absent credential or rejected authentication, open `start_local_ui` with `page: setup`, or run `.\cse.cmd setup`. Explain how to obtain a PAT when needed: Canvas → Account → Settings → **+ New access token** under Approved Integrations. The teacher supplies the Canvas address and PAT in the private local form; the token goes to Windows Credential Manager. Never receive it in chat, a terminal, a file or a note, and never fetch the private form. Give its returned local URL only as a browser fallback. A timeout, DNS/TLS/proxy error, district restriction, Canvas outage or server error is a connectivity problem, not evidence the saved PAT needs replacing. Explain that specific failure, retain saved credentials and courses, and continue offline drafting or teaching-context setup. An ambiguous permission failure may be course access rather than a rejected token; do not infer credential replacement. Setup records the Canvas address in `context/courses.md`.
3. **Configure missing or additional courses.** If the saved structured list already contains the requested courses, keep it and continue; do not repeat completed setup. When the teacher needs additional courses, `list_courses` with `source: canvas`, or `.\cse.cmd courses`, lists the Canvas catalog and IDs. Show the teacher the list and ask what they call each class they want to use, and which are current (the ones a "scoring session" should scan). Write their answers to `context/courses.md` (field reference in `help formats`); don't infer nicknames from Canvas titles.
4. **Student notes.** `.\cse.cmd students` changes aliases and monitored status. Teacher-written accommodations and notes go in `context/students.md`, tied unambiguously to a student and course; real names are fine there. Offer this; don't require it.
5. **School calendar.** Lateness depends on `context/school-calendar.md`. Ask the teacher for the school's first and last days and holidays (or a calendar link or file) and fill it in. Offer this; don't block other work on it.

6. **Teaching preferences, when useful.** Read `context/teaching-profile.md`, `context/grading.md` and existing teacher reference notes first. Offer to carry over existing teaching instructions the teacher selects, or briefly ask about grade/subject, instructional priorities, standards and feedback voice. Save broader preferences in the plain teaching profile and feedback voice/guidance in `grading.md`, merging with the teacher's existing content instead of replacing it. With MCP, read each current file and supply its SHA-256 when replacing it; on conflict, reread and preserve intervening edits. Keep unknown details unspecified and course-specific choices distinct. Do not import this developer's ELA7 classes or Silver/Red/Blue policies into a colleague's profile. A teacher may skip this and begin work; ask for the next useful detail as tasks arise, rather than requiring a questionnaire.

Then do what the teacher originally asked.

For typed MCP rules setup, use `engine_info` with `operation: "rules-location"` for status. After the teacher supplies an absolute directory, use `operation: "set-rules-location", sync_root: "ABSOLUTE PATH"`; an empty `sync_root` explicitly returns to Install. Status mode is `local` or `sync`. Preserved local originals are in private `.cse/rules-archive/`; do not bypass private file exclusions to inspect them.

The hub and MCP use the same Install and its per-Install rules binding. Teacher `AGENTS.md`, `CLAUDE.md`, playbooks, custom root guides and context references use Sync when configured. Product README.md, commands, `context/courses.md`, `context/students.md`, student mappings and `courses/` work stay local. `list_courses` reports Install's root, instance and saved `current` flags; another configured read sees hub changes without a restart. Rule edits likewise appear on the next read. An existing MCP registration pointing at an old Install needs to be re-registered for the intended Install and restarted, rather than recreating course choices there.
