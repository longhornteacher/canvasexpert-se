# Set up CE-SE

Use `install.md` first when the teacher says "set this all up," "set this up," or "install this" or needs Claude or ChatGPT connected (it connects every supported app it finds: Claude, ChatGPT and Antigravity). This playbook handles Canvas, courses and progressive teaching context after Engine access exists. Do this the first time, and on each new computer (the Canvas credential stays on each machine). The teacher only talks to you and enters their Canvas token in the local form; you do everything else, including editing `context/` files.

Work in **UserInstall**, the local runnable CE-SE folder. **Dev** is for developing the product. Optional **UserSync** is a dedicated locally accessible cloud directory holding authoritative teacher rules; the provider synchronizes it. The default needs only UserInstall. MCP's "workspace" remains UserInstall, and logical rule paths use the same active files as the hub.

For shared rules across PCs, first inspect `engine_info` rules-location status or `.\cse.cmd rules-location`. Only after the teacher supplies a dedicated directory, select it in Settings → Where your teacher setup lives, or use `.\cse.cmd rules-location --sync "PATH"`. An empty directory starts from this UserInstall's actual customized rules; an existing directory wins without importing this PC's differing rules. Original local instructions are preserved and become inactive. After binding an existing directory, review Settings → Playbooks and context files, or use `engine_info` with `operation: playbooks-status` / `.\cse.cmd playbooks status`, to compare seed-managed files. Differences may be teacher preferences; do not replace them automatically or guess that they are obsolete. Adopt only files the teacher selects through Settings or the explicit replace operation; the previous file is archived. If the active `AGENTS.md` visibly points to another UserInstall, do not follow that pointer or register/edit that UserInstall. Explain it and offer the current instruction file through the same explicit adoption route. On each PC, configure its own local path to that same provider directory. Do not point MCP registrations or `--workspace` at UserSync. No manual copying between PCs is required. To return explicitly to local rules, use Settings or `.\cse.cmd rules-location --local`; current readable shared rules are preserved locally and differing local files are archived. If UserSync is unavailable, restore access or explicitly select another rules directory; do not read inactive local copies.

1. **Read saved setup and check the Engine.** Read `list_courses` with its default `source: configured`, or inspect the structured `courses` list in `context/courses.md`. Keep saved nicknames and current selections; ignore obsolete starter text in the body. This configuration read needs no Canvas credentials or network. Run `.\cse.cmd version`. If it says the program was not found, the folder is incomplete: ask the teacher to unzip the full CanvasExpert-SE download again.
2. **Connect this computer.** Try `list_courses` with `source: canvas` through MCP, or `.\cse.cmd courses` locally. Success means the saved connection works; preserve it and continue. If the Engine specifically reports an absent credential or rejected authentication, open `start_local_ui` with `page: setup`, or run `.\cse.cmd setup`. Use the plain-language token steps and wording in `install.md` (section 3, 'The Canvas form') to guide the teacher; a rejected token may simply have expired (many districts limit token life to about 90 days), so offer to make a new one without redoing courses. The teacher supplies the Canvas address and token in the private local form; the token goes to Windows Credential Manager. Never receive it in chat, a terminal, a file or a note, and never fetch the private form. Show its actual returned local URL as the fallback if the browser did not open; do not invent one. A timeout, DNS/TLS/proxy error, district restriction, Canvas outage or server error is a connectivity problem, not evidence the saved PAT needs replacing. Explain that specific failure, retain saved credentials and courses, and continue offline drafting or teaching-context setup. An ambiguous permission failure may be course access rather than a rejected token; do not infer credential replacement. Setup records the Canvas address in `context/courses.md`. If a message says the saved credential and course configuration use different Canvas addresses, that is a configuration mismatch, not a bad token: show both addresses and let the teacher confirm the right one.
3. **Configure missing or additional courses.** If the saved structured list already contains the requested courses, keep it and continue; do not repeat completed setup. When the teacher needs additional courses, `list_courses` with `source: canvas`, or `.\cse.cmd courses`, lists Canvas titles, codes, IDs and states. Use the ID and state to distinguish similarly named sections and propose the likely current ones (published, current term), then let the teacher confirm. The WebUI course page lists available courses first (the `list_courses` result is in Canvas order); unpublished courses remain selectable but are de-emphasized. Ask which courses they are teaching now and what short nickname they use for each selected course. New selections need a nickname; never infer one from the Canvas title or code. Preserve saved nicknames and current flags, including an explicitly selected unpublished course. Write the teacher's choices to `context/courses.md` (field reference in `help formats`).
4. **Student notes.** `.\cse.cmd students` changes aliases and monitored status. Teacher-written accommodations and notes go in `context/students.md`, tied unambiguously to a student and course; real names are fine there. Offer this; don't require it.
5. **School calendar.** `context/school-calendar.md` supplies the school's IANA timezone, school-year boundaries and non-school dates/ranges for school-time late calculations. Ask for the calendar or dates and fill it in from teacher-provided information. Late timing across school dates needs accurate holidays/ranges; an on-time result needs no calendar interval. Parent reports separately require a valid calendar with a grading period covering the local as-of date; preserve each exact period boundary and correct gaps or overlaps when a parent-report workflow identifies them. Scoring-session discovery has no grading-period prerequisite. Missing calendar details do not block unrelated setup or scoring work.

6. **Teaching preferences, when useful.** Read `context/teaching-profile.md`, `context/grading.md` and existing teacher reference notes first. Offer to carry over existing teaching instructions the teacher selects, or briefly ask about grade/subject, instructional priorities, standards and feedback voice. Save broader preferences in the plain teaching profile and feedback voice/guidance in `grading.md`, merging with the teacher's existing content instead of replacing it. With MCP, read each current file and supply its SHA-256 when replacing it; on conflict, reread and preserve intervening edits. Keep unknown details unspecified and course-specific choices distinct. Never carry any other teacher's classes or policies into this teacher's profile; use only what this teacher says. A teacher may skip this and begin work; ask for the next useful detail as tasks arise, rather than requiring a questionnaire.

Then do what the teacher originally asked.

For typed MCP rules setup, use `engine_info` with `operation: "rules-location"` for status. After the teacher supplies an absolute directory, use `operation: "set-rules-location", sync_root: "ABSOLUTE PATH"`; an empty `sync_root` explicitly returns to UserInstall. Status mode is `local` or `sync`. Preserved local originals are in private `.cse/rules-archive/`; do not bypass private file exclusions to inspect them.

The extracted folder is this machine's UserInstall; its resolved path is shown in the hub (Settings → Engine, and the How and Connect pages) and returned by the install helper as `install_root`. The destination's configured `list_courses` metadata also reports `install_root`; compare these values before teacher work. The hub and MCP use the same UserInstall and its per-UserInstall rules binding. Teacher `AGENTS.md`, `CLAUDE.md`, playbooks, custom root guides and context references use UserSync when configured. Saved course configuration, student notes and private student settings/contacts also use UserSync. Never read private `.cse/` records, including contact JSON. Product README.md, commands and `courses/` grading/planning work stay local. `list_courses` reports UserInstall's root, instance and saved `current` flags; another configured read sees hub changes without a restart. Rule edits likewise appear on the next read. An existing MCP registration pointing at an old UserInstall needs to be re-registered for the intended UserInstall and restarted, rather than recreating course choices. If configured UserSync is unavailable, its path and error remain the active status; do not treat UserInstall copies as active or use them as a fallback.
