# Edit an existing assignment

Canvas Live is authoritative, so always start from a fresh pull. What the teacher's words mean and when to write are in `AGENTS.md`.

Read the relevant course/assignment context under `teacher-context.md`. After an accepted change to prompts, source material, points or rubric expectations, update that assignment's reusable expectations and affected models from the accepted outcomes; keep unsent changes with the local draft. A missing note is not a prerequisite for an edit. Saved guidance never overrides the fresh Canvas pull.

## Pull, edit, push

```powershell
.\cse.cmd pull-item <course> <title-or-link>
```

If several assignments match, choose from the returned candidates with the teacher; don't guess. Edit the pulled file, changing only what the teacher asked. Keep its identity, `observed` baseline and the Canvas HTML you aren't changing.

To move an assignment or New Quiz between gradebook categories such as Daily, Major Grade and Imported Assignments, read the destination course's assignment groups with `canvas_get` (CLI `cse api /api/v1/courses/COURSE_ID/assignment_groups?per_page=100`, following pages) and set `assignment_group_id` to the requested group's exact ID. Group names can differ between courses; do not reuse an ID from another course. A move between weighted groups can change course grades, so say which group is changing and the effect before writing.

When the edit changes wording students will see, run the review in `review.md` on the changed passages. Then tell the teacher here, for each changed field, what it is now and what it becomes (for a long body, the changed passage rather than the whole text), and push on their go-ahead with `.\cse.cmd push <pulled-file>` (MCP: `push_document`). When the request already included making the change, push first and then report. `push` rechecks Canvas: if those fields changed since your pull, it holds and keeps your unsent edit; pull again, reapply the edit to the new version and tell the teacher what had changed. When the teacher asks to see it on a page, `.\cse.cmd review <pulled-file>` reads Canvas at that moment and shows each changed field side by side.

## Edit existing New Quiz content

Use `pull_quiz {course, assignment_id}` (CLI `pull-quiz COURSE ASSIGNMENT_ID`) for the quiz title/instructions or an ordinary question's title, prompt or general/correct/incorrect feedback. `pull_assignment` supplies the associated assignment, not quiz instructions or question text. Read the returned fresh `kind: new-quiz-edit` draft; preserve every identity and `observed` block, and the HTML you are not changing. Identify each requested question by exact `item_id`, its displayed position/type and content; never select a write target by position alone.

Set only requested `changes`: quiz `title`/`instructions`; item `title`/`item_body`/`feedback: {neutral, correct, incorrect}`. General feedback is `neutral`. Omit other fields; use `""` to clear HTML/feedback, never null or an empty title. Validate with `validate_document`, run the review in `review.md` on the changed text, then use `push_document` with the usual conversation check-in; an explicit request to make the edit already authorizes pushing it. The Engine preserves sibling feedback and independent edits. If an action is held, explain the specific conflict, pull again and reapply that edit; retain the unsent draft. Rerun the same draft after failure or uncertain completion: values already live are skipped. Report the returned outcomes rather than claiming a confirmation read or regrading.

Stimulus, Bank, BankEntry, immutable and explicitly noneditable content must be edited in Canvas. A stimulus-linked ordinary question can have its own text edited. Answers, scoring, question types and student grades are separate operations. Attempts do not blanket-block content edits; don't claim a text correction regrades an attempt.

For a revised handout or image, upload it with explicit access and a preserved reusable receipt, keeping the original file. Use the receipt's verified course/file IDs and full Canvas origin to replace only the requested supported HTML reference; don't save expiring signed URLs as source mappings or upload again when resuming the text edit. Follow `native-content.md` and the Engine formats' course-file links. If an attachment/player representation is unsupported, explain that item and continue independent text corrections. Saved API HTML is not proof of student appearance or access.

## Small text corrections

For a small fix to directions, such as a wrong date, a typo or one changed sentence, use `replace_text` (CLI `.\cse.cmd replace-text <course> assignment <assignment-id> --find "<exact text>" --replace "<new text>"`) instead of rewriting the directions. It reads Canvas at that moment, applies only your exact replacements to a fresh pulled file and changes nothing else. Copy each find text from a fresh pull, because Canvas stores HTML (`&amp;`, `&nbsp;`, tags). Each find must match exactly one place; include enough surrounding words, or set `all` only when the teacher wants every occurrence changed. Several pairs apply in order, and nothing is saved unless all of them match. If you pulled earlier, pass its `observed.updated_at` as `expect_updated_at` so a change made since then holds instead of being edited over.

When the replacement is new wording students will see, run the review in `review.md` on it first. Without `push`, the edit is saved, not sent: tell the teacher the passage as it is now and as it becomes, and push the returned file with `push_document` on their go-ahead. When the request already included making the change, set `push: true`. A held result explains why (no match, several matches, changed baseline) and names the fresh pull, so nothing is written. Use the full pull-edit-push path below for larger rewrites or other fields.

## Attach a rubric

To inspect an existing course rubric, use `list_rubrics {course}` (CLI `rubrics COURSE`); add `include_account: true` for school rubrics when permitted. `pull_rubric {course, rubric_id}` (CLI `pull-rubric`) saves a fresh portable definition for reading and planning, and reports usage counts only. An unknown count is not zero. Preserve the returned draft and its wording. Save it into `context/rubrics/` through guarded `write_workspace_file` only when the teacher asks. On an assignment or New Quiz without a rubric, keep the pulled assignment unchanged, set operation to attach-rubric, and supply exactly one full rubric definition, `rubric: {id: N}`, or `rubric: {library: "filename stem"}`. Graded discussion creation accepts the same choices under assignment.rubric. The Engine resolves the exact course/account rubric or the active teacher-setup library, preserves existing attachments, and never edits a Canvas rubric definition. A changed library entry during an unfinished operation holds that operation for a new draft. Rerun the saved draft after failure; known rubric creation and accepted attachment are not repeated.

Use this right after creating a New Quiz with ECR/SCR written items, and whenever the teacher wants a new rubric on an assignment or New Quiz that has none. Shape and word it as `TEACHER.md` describes (STAAR-shaped with in-between ratings, terse lines). Pull it, confirm the pulled `observed` has no rubric, change only `operation` to `attach-rubric`, and add `rubric` with `use_for_grading: false` and its criteria, maxima, descriptions and any ratings. Use local keys for the new criteria and ratings; Canvas assigns real IDs. Then `push` the file within the requested scope; if the rubric design is an open question, describe the proposed rubric in the conversation first.

For a New Quiz, build criteria from each written item's `rubric_hint` in the quiz file when there is one, make each item's criteria total that item's points so rubric scores match the item points written into the quiz, and start each criterion name with its item number ("Q13 Evidence"). A pulled New Quiz accepts `attach-rubric`, or an `update` changing only `assignment_group_id` and base `unlock_at`, `due_at`, and `lock_at`. Preserve the other pulled fields and use the normal assignment edit check-in. These group and date edits also work after attempts. Change question points with `quiz-points` (see `quizzes.md`) and supported quiz text/links with the New Quiz content flow above; stimulus and bank content stays in Canvas.

The attachment keeps the assignment's points and settings and never edits or replaces an existing or shared rubric; an assignment that already has one is refused. If the outcome is uncertain, rerun the same file: it confirms only when the rubric now exists and never attaches twice. If it is still uncertain, check the assignment in Canvas with the teacher, then pull it again. Pull again before scoring so the packet has Canvas's real criterion and rating IDs.

For an individual assignment limited to selected book clubs, read `group-work.md`'s individual-response instructions. Use the nested `audience` source and Engine preparation before the check-in; preserve independent submissions and manual exceptions. Initial audience-only updates use the exact assignment-dates document with its existing rows unchanged; remove the unchanged pulled `only_visible_to_overrides` request and retain its observed baseline so the nested audience alone controls the restriction. Do not hand-maintain recipient lists or substitute native shared-group settings. For later membership changes use explicit `prepare_audience` with `refresh: true` on the saved receipt/latest action, then check in and push the returned assignment-dates path. Preserve protected work, manual exceptions and saved ownership; see `group-work.md` for the agent-driven refresh procedure.

A course Page for selected clubs uses the same `audience` intent and `prepare_audience` call before `push_document`. An audience-only change sends no body or title PUT, so a teacher's live body edit is preserved; availability dates use `unlock_at`/`lock_at` with omit-to-preserve and `null`-to-clear. See `group-work.md`'s Page instructions.

A New Quiz for selected clubs uses the same `audience` intent in `metadata.canvas.audience` and the same `prepare_audience` call before `push-quiz`. The restriction targets the quiz's exact associated assignment, so the quiz stays one gradebook column and each student answers independently. A refused audience never publishes, and a resume repeats only unfinished steps. For later membership changes use explicit `prepare_audience` with `refresh: true`; the returned assignment-dates action changes only who can see the quiz and sends no question or settings write. See `group-work.md`'s quiz instructions.
