# Score student work

For a book-club unit, read `group-work.md` first. The current group workflow supports ungraded discussion evidence and ordinary individual assignment/New Quiz scoring; it supports shared and individual grades on a shared group product (`group-results`; see `group-work.md`), and graded discussions (see the graded-discussion section of `group-work.md`). Do not turn discussion participation counts or a discussion packet into a score. Use this playbook only for a supported individual assessment.

The judgment calls are yours; the Engine pulls work, does the arithmetic and posts. What the teacher's words mean and when to post are in `AGENTS.md`; how to report scores in the conversation is under Report and post below.

Read this playbook and grading/calendar references through their logical MCP paths or from the effective teacher-rules root (UserInstall by default, configured UserSync otherwise). Student notes and course configuration use that same authority. Packets, drafts and commands stay in UserInstall. Contact JSON is private and must not be read for scoring. If a shared reference is unavailable, explain that file's problem without reading an inactive local copy; continue independent work that has its needed evidence.

A rubric shared by several assignments is assessed through the ordinary live rubric and exact criterion IDs. To inspect or offer a reusable rubric for future work, see edit.md; save a personal library entry only when the teacher asks. Never alter an existing definition to fit a grade.

Use `teacher-context.md` for reusable guidance: read this course's notes, this class's open entries in `context/reteach.md`, and the exact assignment's expectations/models from `context/courses/<course-id>/assignments/<assignment-id>.md`. Reconcile origin, IDs, prompts, sources and rubric/points with the normal fresh pull before using them. Authored models calibrate strong, attainable grade-level work; they add no requirements or phrase-matching test. Recalibrate stale guidance for the affected prompt and continue independent work. Missing notes do not block scoring; save useful new assignment guidance and any established local scoring basis/interpretation there without student work or results.

## Pull

```powershell
.\cse.cmd pull-work [course] [assignment] --session
```

For every ordinary scoring session, use `--session`, even when the teacher selects a course or assignment (MCP: `pull_work` with `session: true` and the same optional scope). The targeted session uses Canvas's needs-grading count and includes submitted work that is late, due now or not yet due. It does not filter by grading period; a closed-period assignment is reported without pulling its submissions. A bare “scoring session” means pull everything Canvas reports as needing grading, present the assignment list, then ask what the teacher wants scored. If the teacher already narrowed the request, use the report's assignment group and due-state columns to apply that scope with common sense. Resubmissions after grading are ordinary work and are scored normally. When the Engine writes a New Quiz's item points, Canvas marks the attempt graded and it leaves the session. When it posted only a comment (no item scores), that attempt is not pulled again while Canvas still awaits written-item points; pass the “comment posted, item points not entered” row and its student count to the teacher as a reminder to enter points in SpeedGrader. Use an explicit assignment pull without `--session` when the teacher requests reassessment. In a group session packet, retain every member as audience evidence but assess only members marked `score` or `score-and-late`; a member with no `work_purpose` is already handled. If the packet lists `direction_images` (images embedded in the assignment directions, such as a reference image students must reproduce), read each with `read_workspace_asset` before judging. When an image cannot be read reliably enough for an exact-match check, hold that check and say why instead of guessing. Read the packet and open the student files (see Student files below), especially each row's `work_purpose`: `score` or `score-and-late`. A fresh pull never overwrites unsent scoring work. Before judging anything, read `context/teaching-profile.md` for grade/subject, instructional priorities and relevant standards, `context/grading.md` (the teacher's `voice` and `feedback_guidance`; they override style defaults here, never the rubric or posting rules) and `context/students.md`. Use this teacher's preferences, never another teacher's course/tag policies. Student notes also arrive with each student's pulled work. Apply established accommodations without asking the teacher to repeat them. An incomplete profile does not block scoring when directions, rubric and work supply the needed evidence. In a teammate's course (a course with an `owner`), read `team.md` first: only assignments tagged `(CE)` can be scored, and scores go in hidden for the teammate to post. A session with no course covers only the teacher's own courses.

A partial pull is unfinished discovery, not proof that the class has no other work. Use the successful packet paths and continue independent scoring within the teacher's scope. Report each failed or not-reached assignment and its phase/reason, then use the returned exact-assignment retry inputs if retrieval can be retried; retain `session` and any `group_id` scope. Never replay accepted posts to recover a pull failure. Keep Canvas needs-grading counts, eligible rows, pulled students and attachment/history counts separate. Empty or unmatched quiz reports are unknown evidence, never blank answers or automatic zeros.

New Quiz written items (`ESSAY`, `FILEUPLOAD`) are open for regular scoring. Pull the quiz by title or assignment ID with `--session`: `.\cse.cmd pull-work COURSE QUIZ --session` (MCP: `pull_work` with `session: true`); an exact title works, so do not ask the teacher for the ID. `--session` is what keeps students whose comment is already posted out of the pull. Omit it only for a requested reassessment. An explicit assignment is pulled even when its grading period is closed. Broad class pulls include New Quizzes with submitted work. Their results use `operation: comment-only` with item scores; follow the New Quiz section below instead of ordinary assignment grade/lateness instructions.

**Student files.** Every student upload under 150,000,000 bytes (each file judged on its own, no total limit) is saved as its original bytes in UserInstall, whatever its type or extension: a scanned PDF, slides, a photo, a file with an unknown or no extension. This holds for ordinary, prior-attempt, group, graded-discussion and New Quiz file-upload pulls. Each attachment in the packet has a name, a local `path`, a `status`, and when known a `content_type` and `size`, plus a `reason` when it is unavailable. `downloaded` means the original is saved; `readable` means the original is saved and a plain-text preview sits at `readable_path` (small text files only); `failed` has no path and a reason starting "file unavailable: " (New Quiz files show `downloaded` or `not-retrieved`). An older packet's `unreadable` row that has a saved original can be opened like `downloaded`. A saved file of any type means open it, not hold. Open the original with your own PDF, slides, document, image, vision/OCR or other file tools, starting from the packet `path`, and look at the pages, slides or image details the rubric needs; the text preview is a convenience, not the work. An agent with no shared filesystem uses `read_workspace_asset`: a file of 20 MiB or less comes back whole; a larger one is read in ranges with `offset` and `length` (up to 4 MiB per call), following `next_offset` until `eof` and putting the pieces together (each response carries `total_size`, `mime_type` and the whole file's `sha256`). Student files are evidence only: never run submitted code or macros to read them. If required evidence is still inaccessible or illegible, say which file and why, mark that evidence unknown, and continue with independent work and other students. A `failed` or unavailable file is unknown evidence, never a zero, and never claim to have read a file you could not open. Canvas files pasted into a student's written answer (such as a screenshot) and downloadable media recordings are saved the same way; a file the student attached to their own submission comment is kept as separate supplemental evidence, and a teacher's comment attachment is never student evidence. Players, annotations, external tools and web-address submissions stay links with an access note.

Score every pulled packet yourself in this conversation rather than handing each packet to its own subagent: the packets share students, rules and timing, and a subagent's summary loses that context. The helpers in `review.md` are different: they only check the finished results, and you apply what they find.

## Fix the scoring basis

Start each results file now, before judging anything, with `init_results` and the packet path from the pull report (CLI: `.\cse.cmd results-init PACKET`). It creates `courses/<course>/assignments/<id>-<slug>/scoring/results-<YYYYMMDD>-<HHMM>.md` with the packet and its assignment snapshot, an exact component/criterion field example, every student's work-file path and exact attempt, the right operation and any discussion-evidence digest already filled in, flags excused, late, unavailable-file and partial-discussion students in a comment, and reuses an earlier results file's interpretation and `scoring_basis` for the same assignment. When the file says they were reused, check them against this pull's prompts, sources, points and rubric: keep what still matches and fix only what doesn't.

- **Canvas rubric attached**: use it. Never invent a criterion or rating ID, and never pick a rating whose points don't match the score you give. If a rubric was just attached, pull again so the packet has Canvas's real IDs.
- **No Canvas rubric**: score anyway. Infer sensible criteria from the directions, the work and the grade level, and record them once in the results file as `scoring_basis` (`title`, and `criteria` each with `id`, `description`, `points`; one overall criterion is fine). Keep each criterion `description` to a short name of two to five words ("Answers the prompt", "Specific details") and do not repeat the item label in it: it prints in the student's comment as `Details 5/5`. The fuller meaning goes in your private rationale. **Reuse before inventing**, in this order, stopping at the first that fits: the basis `init_results` reused in the results file; the exact assignment's note; then another section's results, only when that note, the teacher or this session's pull shows the same assignment was given there. Don't search other courses on a guess. Confirm prompts, sources and requirements match; a matching title alone is insufficient. Reuse the applicable `scoring_basis` and `interpretation` so every class is scored on one scale, mapping destination item IDs explicitly. Save the reusable basis/interpretation in the assignment note without student rows. Create new criteria only when none exists. If an earlier basis looks wrong, ask the teacher rather than changing scales between classes. It drives the arithmetic and the score lines in feedback, without creating a Canvas rubric. Ordinary assignments receive the grade and comment; New Quizzes receive only the comment. If a real rubric would help (a reusable assignment), offer one in a preview.

Before scoring anyone, identify the required response units from the directions, rubric and submission mode. A choice among prompts is one unit. Infer defensible relative weights from what each unit demands; equal weights are allowed but not automatic. Use `repeated` mapping when the rubric applies to each response, `direct` when criteria already match separate prompts. Record a short private rationale and apply the same interpretation to every student unless a documented accommodation applies. The scoring contract has the exact fields and arithmetic: `engine_reference` topic `formats-results` (CLI `help formats-results`), not the whole format reference. Examples show shape only; read one by name, such as topic `examples/synthetic-results-two`, rather than every example. The shared `interpretation:` block (mapping, rationale, components) is required for scored results; feedback without scores uses the form below. For ordinary assignment grading, start from `engine_reference` topic `examples/synthetic-results-two` (CLI `help examples/synthetic-results-two`), and keep the `assignment:` snapshot supplied by `init_results`. Handwritten files may omit it: the Engine resolves it from `packet` in memory. Validation and review leave the saved file and hash unchanged. Each student's `grade` lists criterion points. For New Quizzes, use the `comment_only` contract below and in `formats-results`; do not copy a grade operation.

## Assess honestly

**Majors.** When scoring a Major, save what students missed most in the assignment's note (`context/courses/<course-id>/assignments/<assignment-id>.md`): each concept, its standard code when known, and how many students missed it, with no names or aliases. The tutorial retake comes after the report (see After a Major, at the end).

- Score a missing required response as missing; don't average only the answered parts. Report missing submissions; don't enter zeros.
- Work whose required evidence you could not open or read (see Student files) gets `evidence: unknown`: hold that student, explain the specific file and reason, and continue independent students within the teacher's posting scope. A saved file is not unreadable until you have tried to open it.
- Compare with the strongest earlier attempt as one whole submission. Never mix parts of attempts or treat a teacher-adjusted grade as proof of stronger work.
- Reassess when the academic requirements or the submission changed. A title, publication, scheduling or HTML-formatting change alone doesn't need it. The Engine holds a post only when points, rubric, grading type or anonymous/moderated/group mode changed. A new attempt shows up on its own; editing posted feedback doesn't requeue an attempt, but the teacher can ask for a reassessment.

## Possible AI use or copying

While reading each student's written work, watch for signs that it isn't the student's own. You flag; the teacher decides. A flag is never a finding of cheating: it doesn't change the score you give, and it never appears in student feedback, comments, handouts, parent reports or student notes. Don't paste student work into a web search, AI detector or any other outside service, and don't cite a detector's score: they are unreliable and the work is private.

Judge only from what's in front of you: the pulled work, the student's earlier attempts and earlier pulled work in this class, the directions and source texts, and classmates' work in the same pull. Signals:

- **Leftover chat text**: "Certainly! Here's…", "As an AI…", "I hope this helps", "[Your name]", an offer to revise, or Markdown (`**bold**`, `#` headings, bullet lists) pasted into a text box.
- **Invented evidence**: quotes, page numbers, events or characters that aren't in the assigned text, or citations that don't exist.
- **Copied text**: identical or near-identical wording between two students (across all sections in the pull), or long unquoted passages lifted from the source text or an outside source you recognize.
- **Not this student's voice**: a sharp change from the student's earlier work in this class: vocabulary, sentence length, spelling and error patterns, or a jump in polish between drafts with no sign of revision.
- **Far above level**: writing well beyond the grade, such as adult or college-level vocabulary, sentence structure, or analytical moves the class hasn't been taught, especially when it's free of the errors seen elsewhere in the student's writing. Weigh it against what you know about the student's level: the course (an on-level section such as ELA7 rather than PAP/advanced, from `context/courses.md` and the teaching profile), the student's readiness or language tier (Silver, or Green for an emerging English writer) recorded in `context/students.md` or pulled notes, or a Silver/Green tier page they worked from, and their earlier work in this class. Pulled work doesn't list a student's tags; don't guess a tier you can't see.
- **Generic AI style**: polished, general prose that never quite engages the specific text or task; stock phrasing ("delve into", "a testament to", "plays a crucial role", "it is important to note", "in today's world", "rich tapestry", "multifaceted"); every paragraph shaped the same; a tidy "In conclusion" that restates the prompt; answering a broader question than the one asked.

Flag a student in any of three cases: one strong signal (leftover chat text, invented evidence, wording matching a classmate or a source, or writing far above grade level from a student known to work at or below it: an on-level section, a Silver or Green tier, or clearly weaker earlier work); at least two independent weaker signals; or writing far above grade level on its own when you know nothing about the student's level, reported as a weak read. No other weaker signal flags alone. From a Blue or PAP student whose earlier work is also strong, far-above-level writing is ordinary and not a flag. Style alone is weak evidence: strong writers, students who revise carefully, and students using documented supports (speech-to-text, translation, a scribe; check `context/students.md` and pulled notes) can trip it. Don't count quoted and attributed text, wording from the directions or teacher-provided sentence frames, or a shared group product. Short or formulaic answers are rarely worth a flag. Follow any AI or academic-honesty policy in `Teacher_Override.md` or `context/grading.md` over these defaults.

Score flagged work honestly as submitted and write the usual feedback, then send the flag and its evidence through `review.md`: only flags the arbiter upholds go in the report (below). Before posting, ask whether to hold flagged students; when the teacher already said to post, post everyone else, hold the flagged students and say so, since a held student comes back in the next session. Keep flags in the conversation; don't record them in a results file or student notes unless the teacher asks.

## Feedback without scores

When the teacher requests comments without scoring, use `operation: comment-only` with `comment_only` containing the exact pulled `attempt`, `header: none` and `feedback`. Omit `components`; no rubric, `scoring_basis` or `interpretation` is needed for those rows. If scores are supplied, the Engine still validates them. Read the packet's student-work files and use their `student_ref` directly; the Engine resolves Canvas identities privately, so never match students by submission timestamps. `engine_reference` topic `examples/synthetic-results-feedback-only` shows one. Reporting and posting follow the last section. This comment does not mark New Quiz written work as scored; the teacher still enters item points in SpeedGrader.

## New Quiz written items

This path supports individual quizzes graded as points, percent, letter grade or GPA scale. Anonymous, moderated and group grading are outside its current scope.

The scoped pull reads typed Student Analysis essay responses and saves uploaded files into the packet's `students/<student_ref>/files/attempt-N/` folder. File records include status (`downloaded` or `not-retrieved`) and a reason when retrieval is unavailable. Open the saved originals as described under Student files. A file that is not retrieved, or that you cannot open or read, is `evidence: unknown`, not a missing response to score as zero. Explain the affected student, file and reason, hold that student's feedback, and continue independent students. The teacher can open the affected file in SpeedGrader.

Use the attached Canvas rubric or a `scoring_basis`, with private authored `rubric_hint`s as guidance when available. Start the file with `init_results` (see Fix the scoring basis); `engine_reference` topic `examples/synthetic-results-new-quiz-comment` shows a filled example. Create `operation: comment-only` per student with a `comment_only` body containing the exact pulled `attempt` reference (`attempt`, `submitted_at`), scored `components`, and `item_scores: true` (the scaffold sets it). Give every interpretation part the `item_id` of the one written item it scores. The Engine then writes each written item's points and its own comment into the quiz, the same save SpeedGrader makes, so the teacher has nothing to type and Canvas computes the quiz total:

- **Item comment** (Engine layout): the item's score `X/Y` in its quiz points, then the part's `feedback` as a quick explanation of the score and the one thing to do better, then `Exemplar:` with the part's exemplar (the Engine shows it at every score). Write the exemplar at the students' grade level and to the assignment's expectations.
- **Whole-assignment comment** (Engine layout): `Score: X/Y (attempt N)` with the quiz total Canvas reports after the write, so it includes auto-scored items and any fudge points. Remarks about the whole quiz go in the closing `feedback`, which follows that line; leave it empty otherwise.

Grades post as soon as they are written: no hiding or manual posting in the teacher's own courses. The write happens after the review in `review.md` and the teacher's go-ahead in the conversation; the teacher handles any cleanup in SpeedGrader afterward. The Engine validates criterion arithmetic; report and post as in the last section. It writes no rubric assessment or late timing.

When a part cannot name one written item (a choice among prompts), leave `item_scores` off for that file: the Engine posts one whole-assignment comment with each part's item points, and the teacher enters them in SpeedGrader.

Item scores use an undocumented internal New Quizzes call, checked live on 2026-10-29. The Engine holds a student, writing nothing, when the quiz was saved in SpeedGrader since the pull, a new attempt arrived, or it cannot read the quiz result. Say which students were held and why; pull again to rescore them, or the teacher enters those points in SpeedGrader. A teacher's fudge points and items not in the results file are kept as Canvas has them. Treat a failure to match the report student and attempt as a skipped student, and rely on the pulled file status rather than assuming retrieval.

## Ordinary assignment grades

For ordinary assignments, post the honest computed score for the current work, even below an existing grade. Never inflate criterion scores or suppress the assessment to preserve a teacher-adjusted grade.

If the course has an honest-effort floor (the `effort_floor` on the course in `context/courses.md`), set `honest_effort: true` on each grade row whose written or creative work is a genuine try. A multiple-choice score is deterministic and gets no floor. On a New Quiz with written items, set `honest_effort: true` in that student's `comment_only` (with `item_scores`) only when you judge the written work a genuine try; a low total alone never counts. The Engine writes the earned item points as always and reports the floor in the outcome: earned total, any adjustment already in the result, the course minimum and the total to enter. It is raise-only and never lowers an existing adjustment. The Engine writes the adjustment itself when the quiz's points equal the assignment's; when the outcome only reports a number to enter, the teacher enters it in SpeedGrader. Quote numbers from the outcome in the check-in; never compute them yourself. The comment states the fudge points added. When you re-score a floored student, keep `honest_effort: true` so the Engine removes or shrinks its own earlier raise; a raise from before that comment line existed is the teacher's, and the Engine leaves it. Leave it off for blank, placeholder or accidental work and for work that is not a real try. Keep the assessment and criteria as earned; the Engine enters the floor when the earned score is lower and adds the "Entered as" line to the comment. In your report, say how many students were entered at the floor (the score spread from `validate` counts them). Canvas applies late point penalties; you don't. These grade and lateness instructions do not apply to New Quiz comment-only results.

When the pull reports timing candidates (`score-and-late` rows), read `gradebook.md` (Lateness in a scoring session) before saving results: you prepare one batch of first-genuine-attempt and accommodation choices with `prepare_late_timing` and attach the proposals to those grade rows. New Quiz comment-only work has no lateness action.

## Feedback

The Engine starts the comment with the computed score lines. You write the rest as plain text in the teacher's voice: specific, respectful glows and grows as rich as the work needs (there is no sentence limit), grounded in the work, including meaningful changes from the strongest earlier attempt. Use sentences, line breaks and blank lines only: Canvas shows Markdown and HTML literally, so `**Glow:**` posts with its asterisks and `- ` stays a plain hyphen. The same applies to a criterion `comment`. `help fields` records what Canvas shows. Full rubric definitions stay in Canvas. The teacher decides the layout. By default the Engine puts all the scores on top: for ordinary grades `Overall: X/Y` (marked `(late)` when your `late_timing` says late) and, when there are several parts, one `Label: X/Y` line per part in assignment points. Under that it lists each part's rubric lines, then your text, so your text explains the rubric results and what to do better. X is the earned assessment; Canvas applies any late deduction in the gradebook. Order your text as improvement tips, then exemplars. On a New Quiz, `score` and `full` are the same: the scores on top are the Engine's `Questions Canvas scored` line (when pulled) and one line per written part, never an overall line, so apply any saved layout preference (such as "Assessment first") to those lines only and never write an X / Y total for the written portion, even with `header: none`. For any other student, set `header: score` (only the overall line) or `header: none` (the Engine adds nothing and posts your text exactly as written) on the `grade`, `comment_only` or `revise_feedback` body, then put the score where the teacher wants it. The Engine never rewrites the teacher's wording or layout.

### Class exemplars

For each written prompt, pick the two strongest student responses across the teacher's saved current courses that assigned the same prompt; the source course need not be the receiving course. Use short anonymous excerpts: no names, aliases or identifying details. Every student in a receiving class gets the same pair. If fewer than two usable responses exist, use what there is or skip exemplars for that prompt, and say so; never write a model answer and present it as student work.

Exemplars never hold up individual feedback. Post each student's feedback as usual. When the last student whose work answers that prompt is scored, across the courses that assigned it, send the exemplars as a follow-up: a second results file with `operation: comment-only` for each student, `header: none`, no components and the exemplar text as `feedback`. It adds only the comment and never touches the grade, so a grade the teacher changed in SpeedGrader stays as they left it. Post them when the teacher has given the go-ahead for that prompt's feedback.

When a result covers several written items, give each component its own `feedback`, which explains the score and the one thing to do better, and leave the closing `feedback` empty unless something applies to the whole quiz. With item scores each part's feedback becomes that item's comment in the quiz; otherwise the Engine posts one block per item in the comment: `Q11 Remote execution 10/12`, then that item's feedback. Also write an exemplar for each item: a short, complete model answer to that item, in plain text, at the students' grade level and meeting the assignment's expectations. Write it once, as `exemplar` on that part's `interpretation` component, and the Engine adds it to every student's comment; put an `exemplar` on one student's component only when that student needs a different model. Reuse the matched, current authored model from the assignment note when available; otherwise create, review and save one following `teacher-context.md`. It is your model, not a student's work. The Engine shows it at every score. Feedback explains how to improve and does not propose an extra turn-in, correction or grade increase; check any such promise against the applicable teacher policy (`review.md`).

Give each interpretation component the `item_id` of the written item it scores, from the packet's `written_items`: the Engine scales that part to the item's quiz points (a 7/10 rubric result on a 15-point essay is `10.5/15`), which is the number it writes with item scores. A choice among prompts has no single item, so leave `item_id` off that part and `item_scores` off the file. Without item scores the comment leads with `Questions Canvas scored: X/Y` when the pull recorded that subtotal, then one `Label: X/Y` line per written part and each part's rubric lines, never an overall line; a part without `item_id` shows its rubric points. The Engine adds the subtotal from the pulled work; you never supply, restate or add to it. That comment is posted before the teacher enters the written-item points, so Canvas has no complete quiz result yet. Never build a whole-quiz score from the written portion and the subtotal together. A work file whose attempt shows `auto_scored_note` instead has no subtotal; the comment simply omits that line.

## Save, report, post

In the results file you started with `init_results` (see Fix the scoring basis), you fill the interpretation (unless reused), each student's components and feedback; until then it fails validation, so it can never post half-written. Without the tool, write the same file by hand. Run `.\cse.cmd validate <results-file>` to check criterion arithmetic (ordinary grade `assessment` may be omitted; the Engine fills it in). Then run the review in `review.md` on the finished file, including every possible-AI-use flag, and validate again after applying its rulings.

### Report in the conversation

When the scoring is done and valid, report it here rather than sending the teacher to a page. Keep it short, one block per assignment (and per class when sections differ):

- overall impressions: what most students did well, the most common gap or misconception, and anything surprising or concerning, in two or three sentences. Name trends: the same gap in another class, or one already open for this class in `context/reteach.md` ("still mixing up theme and topic, as on the last essay")
- reteach needs you added to or updated in `context/reteach.md` for this class, one line each (see `teacher-context.md`)
- how many students were scored and the distribution in assignment points, including median and rough spread ("median 7/10; most 6–9; four below 5"). Take these numbers from the score spread `validate` prints for a valid results file (MCP `validate_document`): scored and held counts, median, middle half, lowest and highest, percent bands, and how many were entered at the honest-effort minimum (for a New Quiz, the same per written part in item points). Don't count or compute them yourself. Offer one or two hypothetical curve options only when the distribution warrants it and state their numerical effect. No curve is applied; applying one requires a separately requested feature. For a New Quiz, report ranges per written part in item points; Canvas computes the quiz total once item scores are written, so quote a total only from Canvas. Never guess a total or silently apply effort floors to item points or fudge points
- one typical, non-held student’s exact Engine-rendered comment by alias, from `.\cse.cmd validate RESULTS --show STUDENT_REF` (MCP `validate_document {path, show: STUDENT_REF}`). Use the returned text verbatim, never paraphrase it. The sample exposes no submission or private teacher notes; held selections return only the reason. With item scores the sample lists what goes into the quiz: each item's points and comment, then any whole-assignment comment
- each held student by alias with the specific reason, and missing submissions as a count
- possible AI use or copying, headed "For your review", one entry by alias per student whose flag the arbiter upheld: each suspect phrase quoted exactly (a sentence or less each, at most three), the signal it shows ("matches another student's second paragraph word for word" (give that student's alias), "this quote isn't in the novel", "far beyond their last three responses", "college-level syntax from a Silver-tier student in on-level ELA7"), and a plain overall read (strong or weak). Suggest how the teacher could check, such as asking the student to explain a passage or looking at the document's version history. Say nothing about students you didn't flag, and leave this item out when no one is flagged
- late timing that was corrected or held, and any accommodation applied, without the private basis
- for exemplars, which prompts have them ready
- any question the arbiter referred to the teacher, such as "Ten students wrote 'The author's purpose is to show…'. Did that come from you?" When the teacher says it did, treat it as teacher-provided wording for every student

Do not paste every student's feedback. A teacher who wants to read it all can have a Draft PDF of the results file (`save_draft_pdf`): one student per page, held students marked; `handout: true` prints only each student's posted feedback, for handing back on paper. Then ask whether to post. The teacher may ask to see a student's feedback, ask for a change ("go easier on the thesis criterion", "redo Maya's"), or hold someone back. Make exactly the requested change to exactly those students, validate again and report only what changed. A change to the shared interpretation or scoring basis applies to every student. To hold a student back, remove that student's row from the results file before posting; they stay ungraded in Canvas and come back in the next scoring session. Post with `.\cse.cmd post <results-file>` (MCP: `post_results`) when the teacher says to. When the teacher already asked to score and post, post first, then give the same report with the outcomes.

If the teacher asks for a nicer page, write a one-off local HTML file in the course’s scoring folder in UserInstall, using aliases unless names are requested and with no approve or post buttons. Never publish it to a cloud page or sharing service because it holds student work; posting still happens through the conversation.

Report posted, held and failed students from the Engine's output. Explain each held student specifically. Before posting, the Engine checks whether the exact comment text is already present to avoid posting an identical comment twice. Once Canvas accepts a write, treat it as done: do not read it back or rerun just to confirm. If Canvas reports a genuine write error, rerun the same results file to resume; completed writes stay complete. A requested reassessment uses a fresh pull and new results file.

### After a Major: the tutorial retake

Once the teacher has the scoring report and any posting they asked for is done, write, review and privately create the tutorial retake in the same session, as `authoring.md` describes, and tell the teacher in one line that it is ready. The scores never wait on it. If the session ends first, the most-missed list saved in the assignment's note lets a later session pick it up; reuse or resume an existing retake and never make a second. `TEACHER.md` (Majors) says what students never see and that `retake` assign and apply run only when the teacher directs them. Posting the original grades or a low score never triggers either.
