# Create a New Quiz

Use this for any Canvas New Quiz: auto-scored items, written items (`ESSAY`, `FILEUPLOAD`), or a mix such as multiple choice plus constructed responses. What the teacher's words mean and when to create are in `AGENTS.md`.

Before design, read `context/teaching-profile.md`, `context/grading.md` and relevant teacher references. Apply this teacher's grade/subject, instructional priorities, standards and feedback guidance; ask only for missing details that matter to this quiz. Never adopt developer examples as this teacher's policy.

Follow `teacher-context.md`: read the course notes and that class's open entries in `context/reteach.md`, and prepare private expectations and a grade-appropriate model for every written item, including why it meets the rubric. Review these with the quiz. After accepted creation, save them under `context/courses/<course-id>/assignments/<assignment-id>.md` using the associated assignment ID and actual Canvas written-item IDs when available; mark unresolved mappings and pending rubric attachment. Authored QuizForge IDs are not Canvas item IDs. Keep exact-question models private until their intended release, and record useful teacher choices at their proper scope.

Read teacher rules and design references from the effective teacher-rules location (UserInstall by default, configured UserSync otherwise), using logical MCP paths where available. Run commands and save course drafts, assets and outcomes in UserInstall. UserSync holds rules; its provider carries their edits between PCs.

New Quizzes are supported for regular authoring and use, including written-response scoring with `score.md`. Work within the limits below; pending live or student-view verification is not a prohibition or a preliminary test required for each task.

For curriculum conversion, student file assets and placing an existing quiz into a native module, read `native-content.md`. Use the returned New Quiz assignment ID for a module Assignment entry.

## Standards

Apply `TEACHER.md`: items sum to 100 points unless the teacher chooses otherwise (written items about 40% when mixed with auto-scored items), depth at DOK 2-3 in plain, concise wording, choices that survive shuffling, distractors that are real misconceptions of similar length to the answer, and student feedback on every auto-scored item: about two sentences for every MC/MA choice (why the correct answer is the best choice, why each distractor isn't) and for each other auto-scored item (why the correct answer is correct). For a unit quiz, offer spiral items once. After shaping the quiz, check the course's Green tag with `list_tags` and add a Green tier when it has students, then offer Silver/Red/Blue once (Hub section below).

## Write the quiz in QuizForge format

Read `engine_reference` formats and examples (CLI `help formats` / `help examples`), including the embedded `synthetic-quizforge-mixed.md`, before authoring. Write the quiz as a QuizForge v3.0-json file (`<QUIZFORGE_JSON>` or bare JSON). If the teacher has optional QuizForge design modules (`QuizForge_Base.md` and ELA/stimulus references), use them for educational design; the embedded reference defines what this Engine accepts. You write questions, distractors, rationales and points; the Engine handles IDs, scoring structures and Canvas calls. Save the file in the course's `drafts/` folder.

- Give every scored item an explicit `points` value the teacher chose or approved. The Engine won't invent points.
- Put `stimulus_id` on every item attached to a stimulus, including items inside a STIMULUS..STIMULUS_END span. Give each STIMULUS a short student-facing `title` (for example the passage or text name); the Engine makes it a real Canvas stimulus beside its questions. Set `"layout": "below"` for a short passage, code snippet or image that reads better above the questions; leave it out for longer passages students scroll beside the questions.
- Keep HTML to what `help fields` records as kept; the Engine sends it unfiltered. Show code as `<pre><code>...</code></pre>` (colored as Python; add `class="language-html"` or similar to leave it uncolored). Put TEKS codes in `metadata.teks`.
- A course's late-work limit (`late_cutoff_school_days`) sets the lock date when the quiz has none; students with extra time get personal dates from `personal_dates` (`score.md`), and quiz accommodations stay in `set_quiz_accommodations`.
- Quiz settings (time limit, attempts, due date, publication, module) go in `metadata.canvas`. Answer choices shuffle unless `shuffle_answers: false`; leave it on.
- For a quiz only selected book clubs should see, add `metadata.canvas.audience` with `mode: individual`, `policy: snapshot` and the exact `source` set/club IDs, then run `prepare_audience` before the check-in and push. The quiz stays one gradebook column and each student answers independently; the clubs are only the audience. See `group-work.md`'s quiz instructions.
- Quizzes get one attempt by default, with no retakes; add attempts only when the teacher asks or `Teacher_Override.md` sets them. For one attempt, omit `allowed_attempts` and multiple-attempt settings. For two or more set `allow_multiple_attempts: true` and the desired `allowed_attempts`; omit the limit or use `"unlimited"` for unlimited attempts.
- TF uses a boolean `answer`. Feedback goes in root `rationales`, keyed by `item_id`; MC/MA entries contain `choices` with matching choice `id` and `rationale` (and may also carry a top-level `rationale` as general feedback for the whole question), while TF and other auto-scored entries contain `rationale`. Never put `rationale` inside an item or its choices. Every auto-scored item needs an `id` and a `rationales` entry, and an MC/MA entry needs a rationale for every choice; `validate_quiz` refuses the quiz otherwise. Write plain explanation text with no colors or labels: the Engine adds "Why this is the best answer" in green to the correct choice and "Why this isn't the best answer" in red to each distractor (MA: "Why this choice is correct" / "isn't correct"), and "Why this is correct" in green to other auto-scored items. Canvas reliably shows only the feedback for the choice the student picked, so the Engine adds the correct choice's rationale, in green and naming the choice, under every distractor's feedback. Write each correct-choice rationale so it teaches the idea on its own to a student who picked something else, and each distractor rationale so it names the mistake in that choice without restating the whole correct explanation. It removes any colors or labels written into a rationale, so a preference can't change them.
- End the quiz `instructions` with one plain line telling students the feedback is there to use, in words that fit the grade, such as: "After you finish, open your results: every question explains why the correct answer is the best choice and why the others aren't." Then add the quiz corrections offer from `TEACHER.md`, starting with "No retakes." when the quiz has one attempt (the default), such as: "No retakes. You can earn points back: for every question you missed, copy the correct answer's explanation." Add the points amount, turn-in method or deadline only when `Teacher_Override.md` sets them, and leave the offer out only when it says the teacher offers no quiz corrections for points. Don't ask the teacher; follow the default.
- Hot-spot items: `HOTSPOT` takes `id`, `prompt`, `points`, `image` (a PNG, JPEG, GIF or WebP up to 20 MiB, saved in the same folder as the quiz file and named relatively) and `region` (`oval`, `square` or `polygon` with `coordinates` as 0-1 proportions of the image; oval: center then width/height, square: top-left then bottom-right). The Engine uploads the image and the quiz item points at it; do not paste an image URL. Run `validate_quiz` first. A rerun of the same file reuses an already-uploaded image. Tell the teacher the hot-spot shape has not been checked in Canvas Live, so view the unpublished quiz as a student before publishing.
- Written items: `ESSAY` takes optional `word_limit_min`/`word_limit_max`; `FILEUPLOAD` takes optional `accepted_formats`. Write a `rubric_hint` for each ECR/SCR as private guidance for the rubric and scoring: its criteria and ratings, scaled to the item's points as `TEACHER.md` describes. It is not sent to Canvas and does not automatically create a rubric; put anything students must see in `prompt`.

## Quiz styles: MC and MC+Why

A quiz is one of two styles. Use **MC** unless the teacher asks for **MC+Why** (in those words or as "make them explain their answers") or `Teacher_Override.md` makes MC+Why the default. Name the style in the check-in.

- **MC**: the usual quiz, as described above.
- **MC+Why**: every `MC` item is followed directly by a 1-point `ESSAY` asking the student to justify that answer with evidence. Pair every MC item, including recall items: a recall answer still comes from somewhere in the text or lesson, and the student points to it. Other item types (TF, FITB, written items and so on) are not paired.

How to build MC+Why:

- Write the "why" prompt as `Question <n>: Why is that answer the best? Use evidence from the text.` where `<n>` is the number students see on the MC question just above it (Canvas numbers the "why" items too, so the MC items are 1, 3, 5, and so on). For a quiz that isn't about a text, change only the evidence clause to fit the subject, for example "Point to the step or fact that proves it." Don't name a choice letter; answers shuffle.
- Give the "why" item the same `stimulus_id` as its MC item, `"points": 1`, an `id` such as `q4-why`, and `"word_limit_max": 60`. Its `rubric_hint` is the scoring line below.
- Set `metadata.canvas.shuffle_questions: false` so each "why" stays right after its question. Answer shuffle stays on.
- Points: each MC item and its "why" together get an even share of 100, with the "why" worth 1 (10 questions: MC 9 + why 1; 20 questions: MC 4 + why 1). The "about 40% written" rule in `TEACHER.md` doesn't apply to "why" items; it applies only to any separate short or extended responses on the same quiz. If the counts don't divide evenly, propose the nearest clean split.
- Scoring the "why" (1 or 0): 1 when the student gives a reason that points to specific evidence (a detail, quote, line, step or fact) supporting the answer they chose; 0 when it is blank, only restates the choice, or gives no evidence. Score the reasoning on its own: careful evidence for a wrong choice still earns the point, because the MC item already scored the answer. Put this in each "why" item's private expectations (`teacher-context.md`); don't write a model answer per question.
- Don't attach a Canvas rubric for the "why" items; score them with a local `scoring_basis`, one 1-point criterion per "why" item, named with its question number. If the quiz also has short or extended responses, the attached rubric covers only those.

## Check in and create

Run `validate_quiz` on the saved draft first; it checks item shape and settings locally. Correct ignored-field warnings when they affect teacher intent. Then run the review in `review.md` on the whole quiz: items, answer key, every rationale, instructions and tier supports. Validate again after applying its rulings. Then describe the quiz to the teacher here in a few lines: the title, number of questions by type, point total, the effective settings (time limit, attempts, shuffle, when results show) and module placement, how the questions spread across the content, and anything you decided that the teacher did not specify. Don't paste every question; the teacher can ask to see some, or ask for a Draft PDF (`save_draft_pdf`) to look over, or with `handout: true` to print a paper version without the answer key. Make requested changes in the draft and report only what changed. When the teacher says to go ahead, run `.\cse.cmd push-quiz <course> <quiz-file>` (MCP: `push_quiz`). When the request already included creating it, push first and then report. The quiz stays unpublished unless `metadata.canvas.published` is true.

The Engine records the quiz ID in `<quiz-file>.cse.json`. If it reports `partial`, fix the named problem and rerun the same file; it adds only the missing items. If it refuses because a quiz with that title exists, ask the teacher whether it is an unfinished earlier push or a different quiz. For a different quiz, rename this one; for an unfinished push, the teacher renames or deletes the old one in Canvas before you push again. For a club-restricted quiz, a refused or uncertain audience leaves the quiz unpublished; report that plainly and resume the same file, which repeats only unfinished steps.

## Change question points

For existing quiz titles, instructions, question prompts and general/correct/incorrect feedback, follow `edit.md`'s New Quiz content flow: `pull_quiz`, edit the returned draft's `changes`, validate, then `push_document`. Links and course-file references in those supported HTML fields use the same flow. Stimulus and bank content stays editable in Canvas only. This content path does not write answers, points or student scores. In a quiz made before this Engine, a student who misses an MC/MA question may see only why their choice was wrong, because the correct choice's explanation sits only in the question's incorrect feedback (or nowhere, before 1.8.0). When the teacher asks to fix such a quiz, use this flow: for each MC/MA item, set `answer_feedback` for every wrong choice to its own red feedback followed by the correct choice's explanation in the green "Why “…” is the best answer:" form (copy it from the correct choice's feedback or the question's incorrect feedback), and for MC clear the question's `feedback.incorrect` so it isn't shown twice.

`.\cse.cmd quiz-points <course> <quiz>` lists the questions with their positions and points. To change points, add `position=points` pairs, for example `.\cse.cmd quiz-points <course> <quiz> 1=50 2=50`; this works on any New Quiz, including ones the teacher made in Canvas. The teacher's request sets the numbers; follow that requested scope. It changes only the questions named and reads them back. Once any student has submitted, it still writes but warns that Canvas may not regrade existing attempts; tell the teacher to check the gradebook and use the quiz editor's regrade option if scores should change. If it reports that the items' total and the quiz's total differ, tell the teacher; they set the quiz total in Canvas.

## Written items: rubric and grading

When the quiz has ECR/SCR items, attach a rubric right after it is created; don't ask first. Follow "Attach a rubric" in `edit.md`, building the criteria from the `rubric_hint`s: one rubric for all written items, each item's criteria totaling that item's points and named with its item number. For scoring, use `score.md`: pull the New Quiz with `--session` by title or ID, assess typed answers and retrieved files against the attached rubric or a local `scoring_basis`, and prepare each written item's points and comment for the teacher's go-ahead. A missing rubric does not block scoring. CE-SE writes those item points and comments into the quiz, as SpeedGrader does, with no rubric-assessment or late writes; when a part cannot name one item (a choice among prompts) it posts a comment and the teacher enters those points in SpeedGrader.

## What to tell the teacher

Report the quiz URL, the point total, publication outcome and returned sidecar path for resumption. Requested module placement completes before publication. New Quizzes can't be opened as Canvas's Test Student, so a student-side check needs the editor's Build, then Preview, or a real enrolled account. Report actual write outcomes: push does not read item feedback or quiz settings back, so do not claim verified stored rationales or student rendering.

## Differentiated hub for a quiz

Use the hub for the Green tier (automatic when the course's Green tag has students) and for Silver/Red/Blue when the teacher accepts them: add `"differentiation": "hub"` and `tiers` (`label` Green, Silver, Red or Blue; this teacher's exact Canvas `tag` from `list_tags` or the saved mapping in `context/teaching-profile.md`; `supports` HTML). Never invent a tag. Put shared instructions and hints in the quiz `instructions`, with one link per tier whose `href` is `{{tier:LABEL}}` and whose text is the color name alone (`<a href="{{tier:Green}}">Green supports</a>`). Tier content scaffolds the same standard; it doesn't lower it. If a tag doesn't exist, the page is created restricted to nobody and the Engine prints a teacher action naming the page and tag; relay it. Pages publish only with the quiz. A page title that already exists stops the push before anything is created. Students in other tiers see every link but get Canvas's access-denied page for the others.

## Named-student quiz accommodations

When the teacher requests extra minutes, extra attempts or fewer choices for named students on one New Quiz, use `set_quiz_accommodations` (CLI `.\cse.cmd quiz-accommodations COURSE QUIZ_ID REQUEST.json [--preview]`). The request includes its write scope. Target stable refs or unique privacy aliases, with the quiz’s associated assignment ID; report counts and aliases in one line, never the private reason for an accommodation.

Canvas merges a request into the student's existing setting (observed on CS8): send only what the teacher asked to change; omitted fields keep their value, `0` or `false` clears one, and values are absolute, so a repeat adds nothing. Canvas has no read route, so inspect Moderate to see current values; never rerun an uncertain request blindly. The Students page saves private Quiz time and Fewer choices settings. Use `from_saved: true, preview: true` (CLI `--from-saved --preview`) to see the planned count for one quiz without reading or exposing those settings. Without `preview`, `from_saved` applies them in one request and reports counts, naming any failed student by alias. `push_quiz` applies saved settings before publication; if Canvas does not confirm them it keeps the quiz unpublished, so explain the hold and rerun. If the teacher explicitly requests publication without applying saved accommodations, use `skip_accommodations: true` (CLI `push-quiz COURSE FILE --skip-accommodations`) for that invocation only. This skips accommodations, not audience or identity guards; do not suggest it as a routine default. Counts only for saved settings. Course-wide sync remains frozen.
