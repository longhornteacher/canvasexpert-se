# Score student work

For a book-club unit, read `group-work.md` first. The current group workflow supports ungraded discussion evidence and ordinary individual assignment/New Quiz scoring; it supports shared and individual grades on a shared group product (`group-results`; see `group-work.md`), and graded discussions (see the graded-discussion section of `group-work.md`). Do not turn discussion participation counts or a discussion packet into a score. Use this playbook only for a supported individual assessment.

The judgment calls are yours; the Engine pulls work, does the arithmetic and posts. What the teacher's words mean, the review page and how to report are in `AGENTS.md`.

Read this playbook and grading/calendar references through their logical MCP paths or from the effective teacher-rules root (UserInstall by default, configured UserSync otherwise). Student notes and course configuration use that same authority. Packets, drafts and commands stay in UserInstall. Contact JSON is private and must not be read for scoring. If a shared reference is unavailable, explain that file's problem without reading an inactive local copy; continue independent work that has its needed evidence.

## Pull

```powershell
.\cse.cmd pull-work [course] [assignment] --session
```

For every ordinary scoring session, use `--session`, even when the teacher selects a course or assignment (MCP: `pull_work` with `session: true` and the same optional scope). The targeted session uses Canvas's needs-grading count and includes submitted work that is late, due now or not yet due. It does not filter by grading period; a closed-period assignment is reported without pulling its submissions. A bare “scoring session” means pull everything Canvas reports as needing grading, present the assignment list, then ask what the teacher wants scored. If the teacher already narrowed the request, use the report's assignment group and due-state columns to apply that scope with common sense. Resubmissions after grading are ordinary work and are scored normally. A succeeded New Quiz comment for the current attempt is not pulled again while Canvas still awaits written-item points; pass the “comment posted, item points not entered” row and its student count to the teacher as a reminder to enter points in SpeedGrader. Use an explicit assignment pull without `--session` when the teacher requests reassessment. In a group session packet, retain every member as audience evidence but assess only members marked `score` or `score-and-late`; a member with no `work_purpose` is already handled. If the packet lists `direction_images` (images embedded in the assignment directions, such as a reference image students must reproduce), read each with `read_workspace_asset` before judging. When an image cannot be read reliably enough for an exact-match check, hold that check and say why instead of guessing. Read the packet and student files, especially each row's `work_purpose`: `score` or `score-and-late`. A fresh pull never overwrites unsent scoring work. Before judging anything, read `context/teaching-profile.md` for grade/subject, instructional priorities and relevant standards, `context/grading.md` (the teacher's `voice` and `feedback_guidance`; they override style defaults here, never the rubric or posting rules) and `context/students.md`. Use this teacher's preferences, never another teacher's course/tag policies. Student notes also arrive with each student's pulled work. Apply established accommodations without asking the teacher to repeat them. An incomplete profile does not block scoring when directions, rubric and work supply the needed evidence.

New Quiz written items (`ESSAY`, `FILEUPLOAD`) are open for regular scoring. Pull the quiz by title or assignment ID with `--session`: `.\cse.cmd pull-work COURSE QUIZ --session` (MCP: `pull_work` with `session: true`); an exact title works, so do not ask the teacher for the ID. `--session` is what keeps students whose comment is already posted out of the pull. Omit it only for a requested reassessment. An explicit assignment is pulled even when its grading period is closed. Broad class pulls include New Quizzes with submitted work. Their results are **comment-only**; follow the New Quiz section below instead of ordinary assignment grade/lateness instructions.

## Fix the scoring basis

- **Canvas rubric attached**: use it. Never invent a criterion or rating ID, and never pick a rating whose points don't match the score you give. If a rubric was just attached, pull again so the packet has Canvas's real IDs.
- **No Canvas rubric**: score anyway. Infer sensible criteria from the directions, the work and the grade level, and record them once in the results file as `scoring_basis` (`title`, and `criteria` each with `id`, `description`, `points`; one overall criterion is fine). Keep each criterion `description` to a short name of two to five words ("Answers the prompt", "Specific details") and do not repeat the item label in it: it prints in the student's comment as `Details 5/5`. The fuller meaning goes in your private rationale. **Reuse before inventing:** first look for earlier results files for this assignment, and for the same-titled assignment in the teacher's other sections, and reuse their `scoring_basis` and `interpretation` exactly so every class is scored on one scale. Create new criteria only when none exists. If an earlier basis looks wrong, ask the teacher rather than changing scales between classes. It drives the arithmetic and the score lines in feedback, without creating a Canvas rubric. Ordinary assignments receive the grade and comment; New Quizzes receive only the comment. If a real rubric would help (a reusable assignment), offer one in a preview.

Before scoring anyone, identify the required response units from the directions, rubric and submission mode. A choice among prompts is one unit. Infer defensible relative weights from what each unit demands; equal weights are allowed but not automatic. Use `repeated` mapping when the rubric applies to each response, `direct` when criteria already match separate prompts. Record a short private rationale and apply the same interpretation to every student unless a documented accommodation applies. `help formats` has the exact fields and arithmetic; `help examples` shows shape only. The shared `interpretation:` block (mapping, rationale, components) is required. For ordinary assignment grading, start from `synthetic-results-two.md` in `help examples` (MCP: `engine_reference` topic `examples`), but leave out its `assignment:` block: you name the `packet` and the Engine fills the assignment from it. Each student's `grade` lists criterion points. For New Quizzes, use the `comment_only` contract below and in `help formats`; do not copy a grade operation.

## Assess honestly

- Score a missing required response as missing; don't average only the answered parts. Report missing submissions; don't enter zeros.
- Unreadable work gets `evidence: unknown`: hold that student, explain the specific missing evidence, and continue independent students within the teacher's posting scope.
- Compare with the strongest earlier attempt as one whole submission. Never mix parts of attempts or treat a teacher-adjusted grade as proof of stronger work.
- Reassess when the academic requirements or the submission changed. A title, publication, scheduling or HTML-formatting change alone doesn't need it. The Engine holds a post only when points, rubric, grading type or anonymous/moderated/group mode changed. A new attempt shows up on its own; editing posted feedback doesn't requeue an attempt, but the teacher can ask for a reassessment.

## New Quiz written items

This path supports individual quizzes graded as points, percent, letter grade or GPA scale. Anonymous, moderated and group grading are outside its current scope.

The scoped pull reads typed Student Analysis essay responses and attempts to download uploaded files into the packet's `students/<student_ref>/files/attempt-N/` folder. File records include status and a reason when retrieval is unavailable; limits are 50 MB per file and 500 MB per pull. Open downloaded files with your normal document tools. An unavailable or unreadable file is `evidence: unknown`, not a missing response to score as zero. Explain the affected student, file and reason, hold that student's feedback, and continue independent students. The teacher can open the affected file in SpeedGrader.

Use the attached Canvas rubric or a `scoring_basis`, with private authored `rubric_hint`s as guidance when available. Start the file with `init_results` (see Save, review, post); `synthetic-results-new-quiz-comment.md` in `help examples` (MCP: `engine_reference` topic `examples`) shows a filled example. Create `operation: comment-only` per student with a `comment_only` body containing the exact pulled `attempt` reference (`attempt`, `submitted_at`), scored `components`, and student-facing `feedback`. The Engine validates criterion arithmetic and reviews the exact whole-assignment comment. Review is the default; post directly only when the teacher explicitly skips review for this task or has a saved standing preference to skip it. The comment leads with truthful criterion scores and no aggregate quiz assessment. This workflow writes no grade, rubric assessment, per-item score or late timing. The teacher enters per-item points in SpeedGrader.

The report/file transport and comment-only workflow have local tests; separate one-student Canvas Live hand-runs support the APIs and one file download. Engine/MCP end-to-end live verification remains pending. Report that evidence honestly without making a preliminary validation run a prerequisite for regular teacher use. Treat a failure to match the report student and attempt as a skipped student, and rely on the pulled file status rather than assuming retrieval.

## Ordinary assignment grades

For ordinary assignments, post the honest computed score for the current work, even below an existing grade. Never inflate criterion scores or suppress the assessment to preserve a teacher-adjusted grade. Canvas applies late point penalties; you don't. These grade and lateness instructions do not apply to New Quiz comment-only results.

### Lateness

Canvas calculates late point penalties. For work being scored in a session, prepare one batch of first-genuine attempt and accommodation choices with `prepare_late_timing` (CLI: `cse prepare-late-timing FILE`; MCP: `prepare_late_timing` with the packet and student/group choices). Do not re-read or re-time already-scored work in a session. The Engine counts from the applicable deadline to the selected first genuine submission, records school-time provenance, and checks current Canvas state. Use prepared proposals on `score-and-late` grade rows. `late-only` is for an explicit non-session timing task on already-graded work. Never hand-calculate session seconds or substitute a prepared `late-only` row for a grade row. If preparation holds or cannot resolve a timing choice, hold only that timing action and continue the academic assessment when its evidence is sufficient.

1. For each session candidate, use the batch preparation tool against the referenced packet. It confirms the chosen attempt exists in the packet; whether it is the first genuine submission (not blank, placeholder or accidental) is your judgment from the pulled attempts. Later drafts inherit its timing.
2. Read the private `extra_time` fact with the established rules in `context/grading.md`, student accommodations in `context/students.md` and pulled notes, and assignment directions. New pulls include true or false; absence in an older packet is unknown, so refresh that student's evidence when the flag is needed for a timing decision. A documented individual rule takes precedence over a general flag policy; a false flag never cancels a documented accommodation. Neither a bare flag nor a Canvas tag name supplies a duration, multiplier or waiver.
3. Resolve the applicable documented allowance to one absolute RFC3339 deadline using `context/school-calendar.md`. Compare it with the student's pulled `effective_due_at` and the documented base deadline: if Canvas's individualized date already includes the allowance, use that date once. Never add the allowance twice. When using an accommodation, send the resolved `accommodated_deadline` and a private `accommodation_basis` in that student's batch choice, including when the resolved deadline equals Canvas's date. Keep the pulled Canvas date as the `due_at` write guard; the Engine preserves it independently of the counted deadline.
4. The Engine counts from the resolved deadline to the first genuine submission in the calendar's IANA timezone, excluding weekends and listed holidays/non-school ranges while preserving partial-day seconds. Weekdays, including early-release days, count as full calendar dates. An on-time result needs no school-time interval. Review the returned timing, private basis and skipped dates.
5. For a `score-and-late` candidate, attach the prepared proposal's `late_timing` to its grade row. For `late-only`, use only the prepared attempt and timing fields. The Engine rechecks the attempt, live due date, observed timing and school-calendar calculation before writing lateness. A timing hold does not block an otherwise valid grade or comment.

If `extra_time: true` has no usable documented allowance, hold only that student's timing correction and explain the missing rule. Omit their unresolved choice from preparation and continue valid academic scoring and other students' timing. Ask once for the applicable rule when needed; save a teacher-provided standing flag policy in `context/grading.md`, or an individual accommodation in `context/students.md`, through the existing teacher-context workflow. The Engine does not interpret the flag or invent an allowance. Keep the flag and accommodation basis out of student comments, shared feedback and parent reports.

For a scoring session, prepare the resolved timing candidates for work being scored as one batch before saving results and report any unresolved candidates as held. The typed MCP preparation accepts `packet`, `students`, and `groups` inline; the CLI reads a `late-timing-decisions` file under `courses/`. Inspect proposed, unchanged and held rows. Attach proposals to matching grade rows where `work_purpose` is `score-and-late`. Report corrected or unchanged timing and any held candidates with scoring outcomes. Preparation is read-only; review remains the default before any write. See `help formats` for the complete field shape and synthetic example.

If the due date, first genuine work, calendar coverage or accommodation details are unclear, omit timing for that student or keep the late-only row held, say what's missing, and continue independent work. Extra time changes timing, never the score or feedback. New Quiz comment-only work has no lateness action.

## Feedback

The Engine starts the comment with the computed score lines. You write the rest as plain text in the teacher's voice: specific, respectful glows and grows grounded in the work, including meaningful changes from the strongest earlier attempt. Full rubric definitions stay in Canvas. The teacher decides the layout. For ordinary grades the Engine leads by default with `Overall: X/Y`, marked `(late)` when your `late_timing` says late, then one line per item with its criterion scores, then your text. X is the earned assessment; Canvas applies any late deduction in the gradebook. Order your text as improvement tips, then exemplars. On a New Quiz, `score` and `full` are the same: the comment leads with the criterion lines and never an overall line, so apply any saved layout preference (such as "Assessment first") to those criterion lines only and never write an X / Y total for the written portion, even with `header: none`. For any other student, set `header: score` (only the overall line) or `header: none` (the Engine adds nothing and posts your text exactly as written) on the `grade`, `comment_only` or `revise_feedback` body, then put the score where the teacher wants it. The Engine never rewrites the teacher's wording or layout.

### Class exemplars

For each written prompt, pick the two strongest student responses across the teacher's saved current courses that assigned the same prompt; the source course need not be the receiving course. Use short anonymous excerpts: no names, aliases or identifying details. Every student in a receiving class gets the same pair. If fewer than two usable responses exist, use what there is or skip exemplars for that prompt, and say so; never write a model answer and present it as student work.

Exemplars never hold up individual feedback. Post each student's feedback as usual. When the last student whose work answers that prompt is scored, across the courses that assigned it, send the exemplars as a follow-up: a second results file with `operation: comment-only` for each student, their same scores, `header: none` and the exemplar text as `feedback`. It adds only the comment and never touches the grade, so a grade the teacher changed in SpeedGrader stays as they left it. Review follows the teacher's usual review choice.

A New Quiz comment leads with the per-item criterion lines and never an overall line. It is posted before the teacher enters the written-item points, so Canvas has no complete quiz result yet. Never build a whole-quiz score from the written portion.

## Save, review, post

Start each results file with `init_results` and the packet path from the pull report (CLI: `.\cse.cmd results-init PACKET`). It creates `courses/<course>/assignments/<id>-<slug>/scoring/results-<YYYYMMDD>-<HHMM>.md` with the packet, every student's exact attempt, the right operation and any discussion-evidence digest already filled in, flags excused, late, unreadable-file and partial-discussion students in a comment, and reuses an earlier results file's interpretation and `scoring_basis` for the same assignment. You fill the interpretation (unless reused), each student's components and feedback; until then it fails validation, so it can never post half-written. Without the tool, write the same file by hand. Run `.\cse.cmd validate <results-file>` to check criterion arithmetic (ordinary grade `assessment` may be omitted; the Engine fills it in). Then `.\cse.cmd review <results-file>` as in `AGENTS.md`, or `.\cse.cmd post <results-file>` only when the teacher skipped review.

The page approves everyone by default and calls out held students. After Revise, fix exactly the noted students and nothing else; the others keep their approval. If the command is interrupted or the teacher says "check revisions", read `<results-file>.review.json` (items with `"status": "revise"`). Never `post` students who were revised or held. Explain each held student specifically.

Before posting, the Engine checks whether the exact comment text is already present to avoid posting an identical comment twice. Once Canvas accepts a write, treat it as done: do not read it back or rerun just to confirm. If Canvas reports a genuine write error, rerun the same results file to resume; completed writes stay complete. A requested reassessment uses a fresh pull and new results file.
