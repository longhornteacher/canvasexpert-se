# CanvasExpert-SE

The teacher's local CE-SE **Install** holds the runnable Engine, local course/student configuration, drafts, pulled work and private state. **Source** is the development project (code, starter templates and build/release artifacts); optional **Sync** is a dedicated locally accessible OneDrive/Google Drive directory for authoritative teacher instructions, playbooks, guides and preferences. The provider synchronizes it; each Install reads and edits those files directly. Without a binding, teacher rules remain in Install. Claude Code/Codex use Source for development and Install for teacher work; Claude Cowork/GPT Work normally use Install. This skill gets you to Install; teachers do not need Source or Sync. In teacher tools, "workspace" means Install, and existing tool names stay unchanged. MCP does not require another Install.

Logical MCP rule paths use the active authority. `context/courses.md`, `context/students.md`, course work and private state stay in Install. Inspect `engine_info` rules-location status for Install and rules roots; only configure a dedicated Sync directory the teacher explicitly supplies. Keep registrations, commands and work paths pointed at Install. Local-agent bootstraps identify the shared instructions. If Sync is unavailable, report the path problem instead of using inactive local copies; continue independent operations. Rule edits appear on the next read without restarting MCP.

New Quizzes, including `ESSAY` and `FILEUPLOAD` written responses, are supported for regular authoring, use and scoring within Install's playbooks. Pending verification is not a blanket prohibition or a preliminary test required for each task. Scoring produces criterion scores in a comment for review; the teacher enters per-item points in SpeedGrader.

Read the current `context/teaching-profile.md`, grading preferences and relevant teacher references before educational judgments. Offer teacher-selected instruction carryover or gradual onboarding; preserve existing content and do not import developer class/tag policies. An incomplete profile does not prevent ordinary work. The short `TEACHING-ASSISTANT.md` starter sets the destination role without copying authoritative playbooks into client instructions; actual destination tool reads establish readiness.

1. **Find Install's instructions.** For "install this", use the extracted folder's bundled Engine and read its `playbooks/install.md`, even if another CE-SE MCP server is already connected. Never configure the teacher against an unrelated Install or hand them terminal commands. For teaching tasks, when CE-SE MCP tools are connected, read `AGENTS.md` with `read_workspace_file`; use `list_workspace_files` to discover the relevant playbook/context/course files. MCP already targets Install, so separate folder sharing is unnecessary. Otherwise find the folder containing `AGENTS.md`, `playbooks/`, `context/` and `cse.cmd`; only if neither route works, ask the teacher to share their extracted Install with the installation assistant. Don't work from memory of how CE-SE behaves.
2. **Read its `AGENTS.md`, then only the playbook the task needs.** Those files belong to the teacher and override anything here. `AGENTS.md` explains how to reach the Engine from where you are working.

3. **Read saved courses first.** `list_courses` defaults to `source: configured` and returns the installation `root`, Canvas `instance`, and saved nickname/id/current/timezone fields without a Canvas connection. Read it again after hub changes; no MCP restart is needed. Use `source: canvas` only for connection testing or choosing additional courses. Treat the structured courses list as authoritative setup status, ignoring obsolete starter text in a preserved document body. An old-folder registration needs re-registration for the intended CE-SE installation; do not recreate completed setup in the wrong folder.
4. **Prefer connected CE-SE MCP tools when available.** They cover supported Engine reads, local files/assets, validation, authoring, posting, point changes, and local pages. Follow the mapping in Install's `AGENTS.md`. Review is the default for gated writes; direct tools follow an explicit teacher request to skip review, or a playbook-permitted resume. Preserve requested scope, honest assessments, hashes, receipts, and returned outcomes. New Quiz scoring posts only a comment with criterion scores, never an aggregate assessment, grade, rubric assessment or late timing.
5. **Never open, list or search `.cse/`, or inspect private setup/student browser pages.** MCP blocks private file paths; retain this rule when other tools can see the folder. Present private page links for the teacher to operate. Read-only API JSON can contain real names; keep teacher-only information out of student output.
