# Student uploads and grading offers

Development handoff, 2026-11-13. Source audit of Dev at `545b848`, one commit ahead of fetched `origin/dev`. The changes below are proposed. The audit used repository sources and existing test cases. It did not exercise an agent client or Canvas Live.

## 1. Give the agent the original student upload

For each in-scope student upload, save the original bytes in UserInstall and give the connected agent a usable way to open them. A scanned PDF, slide deck, photo, unfamiliar extension or file without an extension qualifies. A successful download establishes that the file is available. The agent judges whether it can see enough of the work to score it.

**Proposed size boundary.** Interpret “under 150 MB” literally as fewer than 150,000,000 bytes per file. Use the same boundary in metadata checks, streaming checks, help and tests. Apply it to each file independently. Four students submitting 140 MB each should all get their work pulled. Existing scope selection, attempt and student identity, group audience checks and preservation of unsent work still apply.

## 2. Remove default offers of extra submissions, extra credit and correction points

With no applicable teacher instruction, a new assignment, quiz or feedback comment should make no offer of another submission, extra credit or points for corrections. During a Major scoring session, create the separate tutorial retake and leave it unpublished and unassigned. Preparation is part of scoring. A student-facing offer, assignment or publication requires explicit teacher direction. Keep worked examples, feedback on how to improve and explanations for missed questions.
